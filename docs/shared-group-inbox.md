# 共享群 inbox 与版本化发言

当前群正文发布/沉默规则已由 [群聊正文默认发布与静默结束](group-default-replies.md) 更新；下文冲突描述保留为历史记录。

2026-09-17：按用户新要求替代逐成员群收件箱，及上一版“普通群回复不触发其他成员”的规则。群 inbox 就是群聊的公开消息流。

## 数据与调度

- `messages` 保存唯一的群正文；`roomVersion` 标识发送时的群版本，`Room.version` 是当前共享版本。用户发言和显式 `room send` / `draft resolve` 成功提交共用这条流。普通模型文本不进入公共消息流。
- 不为公共群消息创建每成员 `Receipt`。`Receipt` 仅保留私有通知/内部委派用途。
- `sceneNotices[Agent × Room]` 保存一个处理位置；`memberSince` 保存加入时的位置，避免仅加入群就启动历史任务。这些位置不复制正文，也不改变共享 inbox 的内容。
- 调度器从共享流找当前位置之后的其他成员消息，合并批次触发 SDK；自己发言不再次触发自己。Agent 根据内容与版本决定发言或沉默，没有新输出就没有新版本，也不会重复触发同一批内容。
- 用户发消息仍自动唤醒成员；停止、未知执行、并发限制维持原边界。正常共享变化不会绕过已停止状态。
- 旧数据自动迁移：保留原群消息及 ID，补充消息版本，保留成员调度位置，只移除公共消息的冗余个人回执。内部结果和回执保留。迁移标记持久化，重启不重复迁移。

## 读取协议

`raftctl inbox list --room ROOM --after-version V --limit 20 --json` 返回同一群的共享 `messages` 与 `version`。默认 V=0，包括自己发过的消息。继续分页时保留全部参数，cursor 固定版本；`currentVersion`/`changed` 提示并发更新。全文过长会标记截断，可用 message get 展开。

同一个群所有成员的公共 messages 与 version 相同。个人 `notifications` 是独立字段，只有接收者能看到，绝不混入公共数组。私聊 inbox 保留原私有通知行为。

公共消息不因 `inbox ack` 被移除或变成其他人的已读；该命令只实际确认私有通知。现有 message 查询中的 unread/unreadCount 兼容字段，对公共群消息表示“还未进入该成员调度的消息”，不再代表个人已读回执。新流程推荐使用共享版本查询。

## 决定发送与并发冲突

1. Agent 读取共享 inbox 的内容与版本，判断有无新增贡献。
2. 区分用户与成员消息：用户问候、试探和不完整问题应自然接话，不要求先有专业任务；发送前读取最新 inbox，已有充分回应则避免重复。被点名、追问或有不同贡献仍可回复。成员之间无补充则结束。SDK 普通文本和 result 只进入当前场景的执行详情，不创建群消息、预览或草稿，也不转发私聊。
3. 公开发言只能显式调用 `room send`，提供实际读取的 `basedOn` 与 `requestId`。不再由宿主自动填写或更新发送版本。`Store.publishReply` 拒绝群消息，避免自动发布路径回归。
4. 版本冲突返回 held、draftId、basedOn、currentVersion、四种操作和 changes 摘要（最多 8 条公共消息，每条 500 字，标注截断与更多消息）。成员/任务也可能改变版本，因此摘要不是完整房间状态，应继续查询。
5. Agent 可在当前 SDK 工具循环内读取变化，调用 `draft resolve` 修改、重试、丢弃或明确 force。retry/revise 继续校验版本；同一操作重试复用 requestId，改稿用新 requestId。
6. 合并运行提示保留。群消息发送成功后整体显示；暂不实现公开草稿的流式预览。私聊继续实时显示与保存已输出文本。停止群运行不把普通输出保存为草稿，已明确发送的消息不自动撤销。
7. 当前 sceneNotices 仍是启动时推进的调度位置，并不表示模型已理解或任务已完成。正文按需拉取与更细的阅读/完成状态不在本次改动范围内。

这不是重新实现 SDK 执行循环：只在应用的共享状态、发布事务与展示层增加约束。内部委派仍私有，群内容不会写入私聊。

- https://code.claude.com/docs/en/agent-sdk/custom-tools

复用 `query`、按场景 `resume`、`UserPromptSubmit`、`PostToolBatch.additionalContext` 及 `includePartialMessages`。继续使用 SDK 内置 Bash → raftctl CLI，而非新增 MCP 工具。结构化输出只在最终结果返回，不适合本次同轮发送冲突反馈；SDK 提供消息流和注入扩展点；应用的 SQLite 群公开流、版本事务、草稿和多用户展示继续由本地宿主管理。

## 界面

群内所有活动成员共享一条运行提示：叠放头像、运行成员名称和一组三点动画；成员开始/结束时更新这一条。私聊保持单 Agent 的头像与加载动画。停止按钮仍停止当前会话，不影响别的会话。

## 验证范围

自动化覆盖共享读取一致性、自己的发言可见、增量版本分页、并发快照、旧版本草稿、读取新版本后提交、成员沉默后不重复启动、迁移幂等与私有通知隔离。浏览器覆盖多成员合并提示、成员数量变化、手机布局、流式与停止、上下文与旧功能回归。不调用真实模型。

本轮验证：`npm run check` 通过（75 项测试、类型检查与生产构建）。测试覆盖群普通文本/结束结果不发布、显式发送后的总结不重复、同轮 held 修订、幂等重试、私聊流式及会话停止隔离。`chat-streaming-smoke` 浏览器验证通过：群普通文本无气泡/预览，显式发送可见，合并动画与手机布局正常，私聊流式、停止和再次发送正常。未调用真实模型。旧群消息和旧 held 草稿保留，不自动清理。

## 用户接话规则修正

系统提示、场景上下文、调度输入与协作 Skill 统一区分用户交流和成员去重。用户的简短消息不能因没有专业任务被集体忽略。保留成员自主判断与版本竞争，不指定固定迎宾 Agent、不自动生成兜底群消息。此规则改善模型决策，但不保证特定模型每次必定调用发送；真实模型接话效果仍需实际使用验证。
